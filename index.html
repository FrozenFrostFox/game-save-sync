Requirements

        

          
🐍 Python 3.8+

          
Download Python if you haven't already. Make sure to check "Add Python to PATH" during install.

        

        

        

          
📦 Google API packages

          
Run this once in a terminal before running any script:

          
pip install google-api-python-client google-auth-oauthlib

One-time setup: your own Google sign-in

      

        
Everyone does this once, on any computer, in about 5 minutes. It's free. It gives the scripts permission to use your Google Drive, and your login details stay with you.

        
    
          
  1. Go to console.cloud.google.com and create a project (e.g. Cloud Save Sync).
    2. 
          
  2. APIs & Services → Library → search Google Drive API → Enable.
    3. 
          
  3. Google Auth Platform → Get started: app name, support email, Audience External, contact email → Create.
    4. 
          
  4. Data Access → Add or remove scopes → add https://www.googleapis.com/auth/drive → Update → Save.
    5. 
          
  5. Clients → Create client → Application type Desktop app → Create → Download JSON.
    6. 
          
  6. Audience → Publish app → Confirm. This is the step that stops the sign-in from expiring every 7 days. It also lets people outside your test-user list sign in.
    7. 
          
  7. Open the downloaded client_secret_….json in Notepad, copy everything, and paste it in Windows step 5 (box under Paste your Google credentials.json). Do this even if you only use Android or Linux: the page uses it to build your rclone setup command. It's remembered in this browser only.
    8. 
        

                
Unverified apps work for up to 100 users. Each person sees a "Google hasn't verified this app" screen the first time. They click Advanced → Go to (app name).

      

    


    


      

        
First-Time Sign-In

        

          

            The first time you run a generated script, a browser window will open asking you to sign in to Google. After you approve, a cloudsavesync_token.json file is saved next to the script — every run after that is automatic.

How to Use the Script

        

          

            1. Download the generated .py (or built .exe).

            2. Run it instead of launching your game normally.

            3. It syncs, launches the game, watches it, syncs again when you quit.

            4. After a clean post-game sync the window closes by itself. If anything failed, it stays open so you can read the error.
          

        

        

        

          
↑ Re-import a built .exe

          
Lost the settings? Use Import script / .exe and pick an exe this page built — it reads the game name, paths, Drive folder and credentials back out of it, so you can tweak and rebuild without retyping.

        

        

        

          
🎯 Exe vs Shortcut

          
Exe alone works for standalone games. Add the shortcut too if a launcher (Steam, Epic…) needs to start first — the exe field should still point at the real game binary so the script knows when it truly closes.

Good to know

        

          
On Android 11+, apps can't read each other's private data folders without root — so native app/game saves only work if the game writes to shared storage, or your device is rooted.

        

        

        

          
Emulator saves almost always live in shared storage already.

How to use the script

        

          

            1. Download the generated .sh file.

            2. Make it executable: chmod +x sync_<game>.sh

            3. Run it (./sync_<game>.sh) instead of launching your game directly.
          

        

      


      

        
Autopilot vs manual

        

          
🎯 With a process name set

          
The script waits for that process to appear, watches it, and runs the post-game sync automatically the moment it exits — same experience as the Windows version.

        

        

        

          
⌨️ Without one

          
The script does the pre-launch sync, then just waits at a prompt — press Enter once you've finished playing to trigger the post-game sync.

        

      


      

        
Finding the process name

        

          
Launch the game once manually, then in another terminal run:

          
pgrep -la <part of the game's name>

          
The second column of the output is the exact process name to use.
